Field Level Validation

✓ AVAILABLE IN PROJECT
What is it? Validation on individual input fields using HTML5 attributes or JavaScript. Each field is validated as soon as user starts typing or moves to next field.

Implementation in RoomSathi:

<input type="email" name="email" required> <input type="tel" name="phone" pattern="[0-9]{10}" maxlength="10"> <input type="password" minlength="8" pattern="^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)"> <input type="text" pattern="^[A-Za-z\s]+$" placeholder="Name"> <input type="number" min="18" max="60" name="age">

Examples in Project:

📧 Email Field

Location: signup.php, login.php, forgot-password.php

Validation: type="email" (validates format automatically)

Error: Shows red border if not valid email format

📱 Phone Number Field

Location: signup.php, profile editing

Validation: pattern="[0-9]{10}" + maxlength="10"

What it does: Only allows 10 digits, won't let you type more

🔐 Password Field

Location: signup.php, reset-password.php

Validation: minlength="8" + pattern (must have uppercase, lowercase, number, special char)

Visual Feedback: Real-time password strength indicator

👤 Name Field

Location: signup.php, profile setup

Validation: pattern="^[A-Za-z\s]+$" (only letters and spaces)

Blocks: Numbers, special characters

🎂 Age Field

Location: profile/setup-step1.php

Validation: min="18" max="60"

Restrictions: Age must be between 18-60 years

Form Level Validation

✓ AVAILABLE IN PROJECT
What is it? Server-side validation that checks entire form when submitted. Verifies all required fields are filled, data is complete, and allows showing multiple errors at once.

Implementation in RoomSathi (signup.php):

if ($_SERVER['REQUEST_METHOD'] === 'POST') { // Get all form data $name = sanitize($_POST['name']); $email = sanitize($_POST['email']); $phone = sanitize($_POST['phone']); $password = $_POST['password']; // Form-level validation (check all fields) if (empty($name) || empty($email) || empty($phone) || empty($password)) { $error = 'All fields are required'; } elseif (!preg_match('/^[A-Za-z\s]+$/', $name)) { $error = 'Name should only contain letters'; } elseif (!filter_var($email, FILTER_VALIDATE_EMAIL)) { $error = 'Invalid email format'; } elseif (!preg_match('/^[0-9]{10}$/', $phone)) { $error = 'Phone must be 10 digits'; } elseif (strlen($password) < 8) { $error = 'Password must be 8+ characters'; } else { // All validations passed, save to database registerUser($name, $email, $phone, $password); } }

Validation Flow:

User submits form
→
Server checks all fields
→
Show error or save data

Data Saving Validation

✓ AVAILABLE IN PROJECT
What is it? Final validation before saving to database. Checks if email/phone already exists, prevents duplicate accounts, and ensures data integrity.

Implementation in RoomSathi (signup.php):

// Before saving, check if email/phone already exists $checkSql = "SELECT id FROM users WHERE email = ? OR phone = ?"; $stmt = mysqli_prepare($conn, $checkSql); mysqli_stmt_bind_param($stmt, "ss", $email, $phone); mysqli_stmt_execute($stmt); if (mysqli_stmt_get_result($stmt)->num_rows > 0) { $error = 'Email or phone already registered'; } else { // Safe to save - email/phone unique $result = registerUser($name, $email, $phone, $password); if ($result['success']) { redirect('/pages/auth/login.php?registered=1'); } }

Data Integrity Checks:

✓ No Duplicate Emails

Before inserting user → Check if email already exists in users table

✓ No Duplicate Phones

Before inserting user → Check if phone already exists

✓ Password Hashing

Before saving → Hash password using password_hash() (cannot be reversed)

✓ Foreign Key Constraints

Database enforces that listings must have valid user_id that exists in users table

✓ Timestamps Auto-set

created_at and updated_at are automatically set by database (cannot be manually changed)

📁 Files: includes/functions.php (registerUser function), signup.php, profile/edit.php

Search Criteria Validation

✓ AVAILABLE IN PROJECT
What is it? Validates search/filter parameters before querying database. Prevents SQL injection and ensures search makes sense (e.g., min rent ≤ max rent).

Implementation in RoomSathi (listings/browse.php):

// Get and validate search parameters $city = isset($_GET['city']) ? trim($_GET['city']) : ''; $minRent = isset($_GET['min_rent']) ? (int)$_GET['min_rent'] : 0; $maxRent = isset($_GET['max_rent']) ? (int)$_GET['max_rent'] : 999999; // Validate: min rent should be less than max rent if ($minRent > $maxRent) { $minRent = 0; $maxRent = 999999; } // Build safe search query using prepared statements $sql = "SELECT * FROM listings WHERE city LIKE ? AND rent BETWEEN ? AND ?"; $stmt = mysqli_prepare($conn, $sql); mysqli_stmt_bind_param($stmt, "sii", $searchCity, $minRent, $maxRent);

Masked Input Validation

✓ AVAILABLE IN PROJECT
What is it? Restricts input format by showing placeholder pattern (mask) and only allowing specific characters. Example: Phone mask (XXX) XXX-XXXX only allows numbers.

Implementation in RoomSathi:

/* Phone Mask - Only allows 10 digits */ <input type="tel" name="phone" maxlength="10" pattern="[0-9]{10}" placeholder="9876543210" onkeypress="return /[0-9]/.test(event.key)"> /* Name Mask - Only allows letters and spaces */ <input type="text" name="name" pattern="^[A-Za-z\s]+$" onkeypress="return /[a-zA-Z\s]/.test(event.key)" placeholder="Enter your name"> /* Number Mask - Only allows numeric input */ <input type="number" name="age" min="18" max="60" placeholder="18-60">

Mask Types in Project:

📱 Phone Mask (10 digits only)

Pattern: [0-9]{10}

Input Filter: Only numbers allowed, blocks letters/special chars

Max Length: Cannot type more than 10 characters

Visual: Placeholder shows "9876543210"

👤 Name Mask (letters + spaces only)

Pattern: ^[A-Za-z\s]+$

Input Filter: Blocks numbers and special characters

Prevents: Invalid names like "John123" or "John@Doe"

Helpful for: Data quality and consistency

🔐 Password Mask (strong requirements)

Pattern: Uppercase + Lowercase + Number + Special char

Real-time Feedback: Shows password strength bar

Minimum: 8 characters required

Visual Indicator: Strength changes from Weak → Fair → Strong

💰 Rent Mask (numeric only, ≥ ₹1000)

Type: number input

Input Filter: Only numbers allowed

Range: Minimum ₹1000

Prevents: Negative or extremely low rent values

📧 Email Mask (standard email format)

Type: email input

Auto-validation: Browser validates email format

Required: Must contain @ and valid domain

Visual: Shows error if format is wrong

How Masked Input Works:

  1. User types character - JavaScript/HTML checks if it matches the mask
  2. Valid character? - Character appears in field
  3. Invalid character? - Character is blocked/ignored
  4. Length exceeded? - maxlength attribute prevents typing more
  5. User submits form? - Server-side validation double-checks pattern

✅ Key Takeaways for Your Teacher

  • ✓ All 6 validation types are implemented in RoomSathi project
  • ✓ Two-layer validation: Client-side (browser) for UX + Server-side (PHP) for security
  • ✓ Never trust client-side alone: Server-side validation prevents hacking/injection
  • ✓ Prepared statements: Prevent SQL injection in all database queries
  • ✓ Real-time feedback: Users see errors immediately (field masks, password strength)
  • ✓ Data integrity: Database constraints prevent invalid data from being saved
  • ✓ User experience: Masked inputs guide users to enter correct format
  • ✓ Security focused: Password hashing, email verification, duplicate checks
