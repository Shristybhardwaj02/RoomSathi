💬 RoomSathi Messaging System - Complete Explanation

How the chat/messaging feature works from start to finish

📌 Overview (In Simple Words)

The messaging system allows two matched users to chat with each other.

Simple Definition: It's like WhatsApp but for finding roommates - User A sends a message → Database stores it → User B receives it.

🗄️ Database Table: MESSAGES

All messages are stored in the messages table with these columns:

Column Name Type Purpose
id INT (PK) Unique message ID
sender_id INT (FK) ID of user sending message
receiver_id INT (FK) ID of user receiving message
message TEXT Actual message content
is_read TINYINT 0 = unread, 1 = read
created_at DATETIME When message was sent
CREATE TABLE messages ( id INT PRIMARY KEY AUTO_INCREMENT, sender_id INT NOT NULL, receiver_id INT NOT NULL, message TEXT NOT NULL, is_read TINYINT(1) DEFAULT 0, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (sender_id) REFERENCES users(id), FOREIGN KEY (receiver_id) REFERENCES users(id) );

🔄 Complete Message Flow: 0 to 100

Step 1: User A Opens Chat Page

What Happens:
  • User A clicks to chat with User B
  • Browser goes to: /pages/chat/conversation.php?user=USER_B_ID
  • PHP code grabs User B's info from database
  • Chat window displays with User B's profile picture and name

Step 2: Load Previous Messages (Get History)

Database Query:
SELECT * FROM messages WHERE (sender_id = USER_A AND receiver_id = USER_B) OR (sender_id = USER_B AND receiver_id = USER_A) ORDER BY created_at ASC;
What This Does:
  • Finds all messages between User A and User B (both directions)
  • Displays them in chronological order (oldest first)
  • Shows "Sent" messages from User A in one color
  • Shows "Received" messages from User B in another color

Step 3: User A Sends a Message

What Happens:
  • User A types "Hi, are you available?" and clicks Send
  • Form submits with POST method
  • PHP inserts into database:
    INSERT INTO messages (sender_id, receiver_id, message) VALUES (USER_A_ID, USER_B_ID, "Hi, are you available?");
  • Message appears on User A's screen

Step 4: Mark Messages as Read

What Happens:
  • When User B opens chat, system automatically marks all User A's messages as "read"
  • Database query:
    UPDATE messages SET is_read = 1 WHERE sender_id = USER_A AND receiver_id = USER_B;
  • This shows "✓✓" (double check mark) for User A indicating User B read the message

Step 5: User B Receives & Replies

What Happens:
  • User B sees the message (auto-loaded or refreshes page)
  • User B types "Yes, I'm interested!" and sends
  • PHP inserts:
    INSERT INTO messages (sender_id, receiver_id, message) VALUES (USER_B_ID, USER_A_ID, "Yes, I'm interested!");
  • User A's page refreshes/auto-loads and shows the reply

🎯 Real-World Analogy

Imagine a Notebook System:

  1. Notebook = messages table (database)
  2. Page in notebook = Each message row
  3. Message Address = From User A to User B
  4. Reading Mark (✓) = is_read = 1 (message seen)
  5. Date on message = created_at (timestamp)

When User A sends a message, it's like writing in the notebook. When User B opens the chat, the system marks that page as "read". That's it!

✅ Key Points to Tell Your Teacher

  • Database: All messages stored in 1 table with sender_id, receiver_id, message, timestamp
  • Sending: INSERT query → adds message to database
  • Receiving: SELECT query → displays messages for that user pair
  • Read Status: UPDATE query → marks message as read
  • Security: Prepared statements prevent SQL injection
  • Ordering: Messages sorted by created_at (oldest to newest)
  • Unique Pair: Each message linked to specific sender + receiver pair

❓ Common Questions Your Teacher Might Ask

Q: How does the system know which messages are for whom?

A: Every message has sender_id and receiver_id. When User A opens chat, system fetches only messages where sender_id = User A or User B, and receiver_id = the other person.

Q: What if User A sends multiple messages?

A: Each message is a separate row in the database. Query will return multiple rows, and code loops through them to display all messages.

Q: How does real-time work? Does User B see messages instantly?

A: Currently NOT real-time - User B needs to refresh page to see new messages. To make it real-time, we'd use JavaScript + AJAX to auto-refresh every 2 seconds or use WebSockets.

Q: How does the system prevent User C from seeing messages between User A and User B?

A: In the query, we filter by both sender_id AND receiver_id. User C's ID won't match, so their messages won't load.

Q: What if 1000 messages are sent? Will it load slow?

A: Currently yes - all will load. To fix this, we'd add LIMIT clause: `LIMIT 50` (load last 50 messages, add pagination to load older ones).
