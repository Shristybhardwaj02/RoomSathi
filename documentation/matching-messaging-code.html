Core Matching Logic - SQL Query

This is the heart of the matching system. It finds mutual matches using a self-join on the likes table:

$sql = "SELECT DISTINCT 
    CASE WHEN l1.user_id = ? THEN l2.user_id ELSE l1.user_id END 
        as matched_user_id,
    CASE WHEN l1.user_id = ? THEN l2.listing_id ELSE l1.listing_id END 
        as their_listing_id,
    GREATEST(l1.created_at, l2.created_at) as matched_at
FROM likes l1
JOIN likes l2 ON l1.listing_owner_id = l2.user_id 
    AND l1.user_id = l2.listing_owner_id
WHERE (l1.user_id = ? OR l1.listing_owner_id = ?)
ORDER BY matched_at DESC";

// Bind parameters
$stmt = mysqli_prepare($conn, $sql);
mysqli_stmt_bind_param($stmt, "iiii", 
    $userId, $userId, $userId, $userId);
mysqli_stmt_execute($stmt);
$matchesResult = mysqli_stmt_get_result($stmt);
How the Query Works:
  1. SELECT DISTINCT: Returns unique matches (prevents duplicates)
  2. CASE WHEN Logic: Determines which user is the "other" person
    • If l1.user_id matches our user → l2.user_id is the matched user
    • Otherwise → l1.user_id is the matched user
  3. JOIN Condition: l1.listing_owner_id = l2.user_id AND l1.user_id = l2.listing_owner_id
    • User A likes User B's listing (l1)
    • User B likes User A's listing (l2)
  4. WHERE Clause: Gets matches for current user as either liker or listing owner

Processing Matches - PHP Logic

$matches = [];
$processedUsers = [];

while ($row = mysqli_fetch_assoc($matchesResult)) {
    // Prevent duplicate matches for same user
    if (!in_array($row['matched_user_id'], $processedUsers)) {
        
        // Step 1: Fetch matched user details
        $userSql = "SELECT * FROM users WHERE id = ?";
        $userStmt = mysqli_prepare($conn, $userSql);
        mysqli_stmt_bind_param($userStmt, "i", 
            $row['matched_user_id']);
        mysqli_stmt_execute($userStmt);
        $user = mysqli_stmt_get_result($userStmt)->fetch_assoc();
        
        if ($user) {
            // Step 2: Fetch their listing details
            $listingSql = "SELECT * FROM listings WHERE id = ?";
            $listingStmt = mysqli_prepare($conn, $listingSql);
            mysqli_stmt_bind_param($listingStmt, "i", 
                $row['their_listing_id']);
            mysqli_stmt_execute($listingStmt);
            $listing = mysqli_stmt_get_result($listingStmt)->fetch_assoc();
            
            // Step 3: Add to matches array
            $matches[] = [
                'user' => $user,
                'listing' => $listing,
                'listing_id' => $row['their_listing_id'],
                'matched_at' => $row['matched_at']
            ];
            
            // Step 4: Mark user as processed
            $processedUsers[] = $row['matched_user_id'];
        }
    }
}
Processing Steps:
  1. Loop through each match from database
  2. Check if user already processed (avoid duplicates)
  3. Fetch matched user's profile information
  4. Fetch their listing that caused the match
  5. Combine data into structured array
  6. Mark user as processed to prevent re-processing

Pending Interests - Secondary Query

Shows who liked the current user's listings but hasn't matched back yet:

$pendingSql = "SELECT l.*, u.name, u.profile_photo, u.age, 
              u.gender, u.city as user_city,
              lst.title as listing_title, lst.id as listing_id
         FROM likes l
         JOIN users u ON l.user_id = u.id
         JOIN listings lst ON l.listing_id = lst.id
         WHERE l.listing_owner_id = ? AND l.status = 'pending'
         ORDER BY l.created_at DESC LIMIT 5";

$pendingStmt = mysqli_prepare($conn, $pendingSql);
mysqli_stmt_bind_param($pendingStmt, "i", $userId);
mysqli_stmt_execute($pendingStmt);
$pendingResult = mysqli_stmt_get_result($pendingStmt);
$pendingInterests = mysqli_fetch_all($pendingResult, MYSQLI_ASSOC);
Why Two Separate Queries?
  • Matched: Both users liked each other - ready to chat
  • Pending: One-sided interest - opportunity to match back

3. Handle Message Submission (Form POST)

if ($_SERVER['REQUEST_METHOD'] === 'POST' && 
    isset($_POST['message'])) {
    
    $message = trim($_POST['message']);
    
    // Validate message is not empty
    if (!empty($message)) {
        // Step 1: Insert message into database
        $insertSql = "INSERT INTO messages 
                       (sender_id, receiver_id, listing_id, message) 
                       VALUES (?, ?, ?, ?)";
        
        $insertStmt = mysqli_prepare($conn, $insertSql);
        
        // Types: i=integer, s=string
        mysqli_stmt_bind_param($insertStmt, "iiis", 
            $userId, $otherUserId, 
            $listingId, $message);
        
        // Step 2: Execute insert
        mysqli_stmt_execute($insertStmt);
    }
    
    // Step 3: Redirect to prevent form re-submission
    header('Location: ' . $_SERVER['REQUEST_URI']);
    exit;
}
Message Submission Flow:
  1. Check if form was POSTed and has message data
  2. Sanitize message (trim whitespace)
  3. Validate message is not empty
  4. Prepare INSERT statement with placeholders
  5. Bind parameters (sender_id, receiver_id, listing_id, message)
  6. Execute INSERT
  7. Redirect to prevent POST resubmission if user refreshes

5. Fetch Message History

$msgSql = "SELECT m.*, 
           CASE WHEN m.sender_id = ? THEN 'sent' ELSE 'received' END 
           as direction
         FROM messages m
         WHERE (m.sender_id = ? AND m.receiver_id = ?) 
            OR (m.sender_id = ? AND m.receiver_id = ?)
         ORDER BY m.created_at ASC";

$msgStmt = mysqli_prepare($conn, $msgSql);

// Bind parameters (all variations of user IDs)
mysqli_stmt_bind_param($msgStmt, "iiiii", 
    $userId,           // For CASE WHEN
    $userId,           // For first WHERE condition (sender)
    $otherUserId,      // For first WHERE condition (receiver)
    $otherUserId,      // For second WHERE condition (sender)
    $userId             // For second WHERE condition (receiver)
);

mysqli_stmt_execute($msgStmt);
$messages = mysqli_fetch_all(
    mysqli_stmt_get_result($msgStmt), 
    MYSQLI_ASSOC
);
Query Logic - Two-way Conversation:
  • First Condition: Messages I sent to them
    • sender_id = ? (userId)
    • receiver_id = ? (otherUserId)
  • Second Condition: Messages they sent to me
    • sender_id = ? (otherUserId)
    • receiver_id = ? (userId)
  • CASE Statement: Marks each message as 'sent' or 'received' for styling
  • ORDER BY: ASC ensures messages show in chronological order

❓ Frequently Asked Questions (For Viva)

Q1: Why do we use CASE WHEN in the matching query?

A: The CASE WHEN determines which user ID is the "other" person. Since likes work in both directions, we need to figure out: if l1.user_id is our user, then the match is l2.user_id. If l1.user_id is NOT our user, then the match is l1.user_id.

Q2: How does the self-JOIN in the matching query work?

A: We join the likes table to itself (l1 JOIN l2). This allows us to find two matching records: one where user A likes user B's listing, and another where user B likes user A's listing. Without the JOIN, we couldn't find this mutual relationship.

Q3: What prevents duplicate matches in the results?

A: We use SELECT DISTINCT to avoid getting the same match twice, and we maintain a $processedUsers array in PHP to skip already-processed users in the while loop.

Q4: How does the messaging system prevent unauthorized chat access?

A: We check if the user is logged in with requireLogin(), validate the URL parameter, and prevent self-messaging. In production, you could add a check to ensure users have actually matched before allowing messages.

Q5: Why do we redirect after POST instead of using AJAX?

A: Redirecting after POST prevents form resubmission. If user refreshes the page, it won't accidentally send the same message twice. This is the "Post-Redirect-Get" pattern.

Q6: How is read status managed in messaging?

A: When a user opens a conversation, all messages from the other user are automatically marked as read using UPDATE query. The message display shows "✓ Sent" or "✓✓ Read" based on the is_read flag.

Q7: What are the 5 parameters in the message fetch query?

A:

  1. $userId (for CASE statement)
  2. $userId (first WHERE - sender_id)
  3. $otherUserId (first WHERE - receiver_id)
  4. $otherUserId (second WHERE - sender_id)
  5. $userId (second WHERE - receiver_id)
