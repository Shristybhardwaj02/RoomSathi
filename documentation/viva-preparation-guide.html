1. PROJECT OVERVIEW 📋

What is RoomSathi?

RoomSathi is a comprehensive room-finding and roommate-matching web application designed to help users find suitable accommodation and compatible roommates in India.

Key Purpose:

  • Room Listings: Users can post room listings with detailed information, photos, and requirements
  • Smart Matching: Algorithm matches users based on preferences, lifestyle, and compatibility
  • Direct Communication: Built-in messaging system for direct user-to-user communication
  • User Profiles: Complete profile system with verification and preferences
  • Admin Management: Admin dashboard to manage users, listings, and handle disputes
💡 Key Insight: The application uses a multi-step matching process that considers user preferences, listing requirements, and past interactions to make intelligent recommendations.

4. AUTHENTICATION MODULE 🔐

Authentication Flow

The authentication system uses session-based authentication with prepared statements for security.

File Location: /pages/auth/

  • signup.php: User registration page
  • login.php: User login page
  • logout.php: Session termination
  • reset-password.php: Password recovery
  • forgot-password.php: Forgot password form

Registration Process

1. User fills signup form (name, email, phone, password)
2. Validation:
   - Check if email already exists
   - Validate email format
   - Validate phone format
   - Password strength check (min 6 chars)
3. Password hashing:
   - password_hash($password, PASSWORD_DEFAULT)
   - Creates bcrypt hash
4. Database insertion:
   - INSERT into users table
   - Auto-verify user (is_verified = 1)
5. Session creation:
   - Set $_SESSION['user_id']
   - Set $_SESSION['user_name']
   - Redirect to profile setup

Login Process

1. User enters email/phone and password
2. Query users table with prepared statement:
   SELECT * FROM users WHERE email = ? OR phone = ?
3. Verify password:
   - password_verify($input_password, $stored_hash)
4. If valid:
   - Create session variables
   - Store user details in $_SESSION
   - Redirect to dashboard
5. If invalid:
   - Show error message
   - Redirect back to login

Key Security Features

  • Prepared Statements: Prevents SQL injection
  • Password Hashing: Uses bcrypt with PASSWORD_DEFAULT
  • Session Security: Sessions stored server-side
  • HTTPS Ready: Can be configured with SSL
  • Input Validation: Email and phone validation

Authentication Helper Functions

// Check if user is logged in
function isLoggedIn() {
    return isset($_SESSION['user_id']);
}

// Require login - redirect if not authenticated
function requireLogin() {
    if (!isLoggedIn()) {
        redirect('/pages/auth/login.php');
    }
}

// Get user details by ID
function getUserById($userId) {
    global $conn;
    $sql = "SELECT * FROM users WHERE id = ?";
    $stmt = mysqli_prepare($conn, $sql);
    mysqli_stmt_bind_param($stmt, "i", $userId);
    mysqli_stmt_execute($stmt);
    return mysqli_stmt_get_result($stmt)->fetch_assoc();
}

6. MATCHING & RECOMMENDATIONS SYSTEM 💕

How the Matching Algorithm Works

The matching system intelligently recommends listings and users based on interactions and preferences.

File Location: /pages/matching/matches.php

Matching Concept

MUTUAL MATCH: When two users like each other's listings
- User A likes User B's listing
- User B likes User A's listing (or one of their listings)
- System marks them as "Matched"
- They can then communicate via messaging

Database Query for Finding Matches

// Find mutual matches
SELECT DISTINCT 
    CASE WHEN l1.user_id = ? THEN l2.user_id ELSE l1.user_id END 
    as matched_user_id,
    CASE WHEN l1.user_id = ? THEN l2.listing_id ELSE l1.listing_id END 
    as their_listing_id
FROM likes l1
JOIN likes l2 ON l1.listing_owner_id = l2.user_id 
                AND l1.user_id = l2.listing_owner_id
WHERE (l1.user_id = ? OR l1.listing_owner_id = ?)
ORDER BY matched_at DESC;

Matching Workflow

  1. Browse Listings: User sees available listings
  2. Like/Unlike: User likes listings they're interested in
  3. Mutual Interest: When both parties like each other
  4. Match Notification: System shows as "Matched!"
  5. Enable Messaging: Users can start chatting

Likes Table States

  • pending: User liked, waiting for response
  • matched: Mutual like confirmed
  • declined: User rejected the listing

Smart Recommendation Features

  • Similar Budget: Show listings in similar price range
  • Same City: Filter by user's city preference
  • History Based: Learn from past interactions
  • Pending Interests: Show who liked user's listings
Match Score Formula:
  • Same city: +20 points
  • Similar rent range (±30%): +15 points
  • Both profiles complete: +10 points
  • Previous positive interaction: +5 points

File Location: /pages/chat/

Messaging Flow

1. User clicks "Message" on a matched profile
2. Conversation page loads with chat history

6. Backend saves to messages table:
   INSERT INTO messages 
   (sender_id, receiver_id, message_text, is_read, created_at)
7. Message appears in chat
8. Other user sees notification
9. Messages marked as read when viewed

Common Questions (For Viva)

Q: How does the matching algorithm work?

A: The system uses mutual likes as the matching criterion. When User A likes User B's listing and User B (or their listing) also likes one of User A's listings, they're marked as matched and can communicate.

Q: What security measures are implemented?

A: We use prepared statements to prevent SQL injection, bcrypt for password hashing, session-based authentication, and input validation/sanitization.

Q: How are user photos handled?

A: Photos are uploaded to the /uploads/ directory with sanitized filenames. The filenames are stored in the database, and full paths are constructed during display.

Q: What happens when a listing is marked as "sold"?

A: The listing is hidden from browse/search results but remains in the database for historical records. Users can reactivate it if needed.

Q: How are admin privileges assigned?

A: Admin status is checked against user ID 1 or specific email (admin@roomsaathi.com). This is verified on every admin page access.

Q: Can users delete their account?

A: Currently, the system doesn't support account deletion, but admin can deactivate accounts if needed.
