📋 Entity Documentation

👤 USERS Entity

Stores user account information and registration details

Primary Attributes:
  • id - Unique user identifier (Primary Key)
  • name - User's full name
  • email - Unique email address (Unique Key)
  • phone - Unique phone number (Unique Key)
  • password - Hashed password
  • profile_complete - Boolean flag (0 or 1)
  • created_at - Registration timestamp
  • updated_at - Last update timestamp

🤝 MATCHES Entity

Records roommate matches between users

Primary Attributes:
  • id - Unique match identifier (Primary Key)
  • user_id - First user reference (Foreign Key → USERS)
  • matched_user_id - Second user reference (Foreign Key → USERS)
  • status - Match status (e.g., 'pending', 'accepted', 'rejected')
  • created_at - Match creation timestamp

🏘️ ROOMS Entity

Stores room/property listings information

Primary Attributes:
  • id - Unique room identifier (Primary Key)
  • location - Room location/address
  • rent - Monthly rent amount
  • description - Room details and description
  • created_at - Room listing creation timestamp

🔗 Relationships

Entity Relationships:
  • USERS → MATCHES (1:Many) - One user can create multiple matches
  • USERS → ROOMS (1:Many) - One user can own multiple rooms
  • MATCHES ↔ USERS (Many:Many) - Matches link two different users together

📌 Legend Notes

  • PK - Primary Key (Unique identifier for each row)
  • UK - Unique Key (Unique constraint on column)
  • FK - Foreign Key (Reference to another table)
  • ||--o{ - One-to-Many relationship (One entity relates to many of another)
  • }o--|| - Many-to-One relationship (Many entities relate to one)
